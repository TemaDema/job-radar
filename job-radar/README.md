# Job Radar — мониторинг IT-вакансий для Беларуси

Система ежедневно собирает новые IT-вакансии с **rabota.by** (hh.ru, Беларусь), **Telegram-каналов** и **LinkedIn**, складывает их в базу и раз в неделю готовит аналитический отчёт с рекомендациями. Рассчитана на человека **без опыта**, который выбирает первую IT-специальность.

## Что делает

- **Каждый день в 08:30 (Минск)** — собирает вакансии за последние 7 дней по ~28 поисковым запросам на rabota.by, читает публичные Telegram-каналы и карточки LinkedIn, отсекает не-IT, обновляет базу и пишет отчёт в `reports/daily/YYYY-MM-DD.md`.
- **Каждый понедельник в 09:00** — считает статистику за неделю и готовит отчёт `reports/weekly/YYYY-Www.md` + краткое резюме в чат.
- **После каждого сбора** — обновляет `reports/dashboard.html` и `reports/recommendation.md`: рейтинг направлений и вывод, какое направление и специальность выбрать.
- Хранит историю: вакансия не теряется, если исчезла с сайта; видно, когда впервые появилась.

## Структура

```
job-radar/
├─ config.json              # что искать: запросы, направления, лимиты, источники
├─ lib.mjs                  # загрузка, парсинг, классификация, навыки
├─ sources/
│  ├─ common.mjs            # общая нормализация внешних вакансий
│  ├─ telegram.mjs          # публичные Telegram-каналы (t.me/s/<channel>)
│  └─ linkedin.mjs          # карточки вакансий LinkedIn (guest API)
├─ scripts/
│  ├─ fetch.mjs             # ежедневный сбор + дневной отчёт
│  ├─ weekly-stats.mjs      # недельная статистика + черновик
│  ├─ export.mjs            # HTML-дашборд + CSV для Excel
│  └─ test-sources.mjs      # проверка Telegram/LinkedIn без записи в базу
├─ data/
│  ├─ vacancies.json        # вся база вакансий (ключ — id)
│  ├─ status.json           # последний запуск, пропуски, история
│  ├─ runs/YYYY-MM-DD.json  # журнал: локальный/облачный сбор, статусы источников
│  ├─ daily/YYYY-MM-DD.json # срез за день
│  └─ weekly/YYYY-Www.json  # статистика за неделю
└─ reports/
   ├─ dashboard.html        # наглядная статистика + итог, что выбрать
   ├─ recommendation.md     # вывод: направление, специальность, план
   ├─ recommendation.json   # тот же вывод в JSON
   ├─ vacancies.csv         # все вакансии для Excel
   ├─ stats.csv             # статистика по дням
   ├─ stats.json            # сводка в JSON
   ├─ daily/YYYY-MM-DD.md
   └─ weekly/YYYY-Www.md    # аналитический отчёт
```

## Ручной запуск

```powershell
# все источники, перечисленные в config.json → sources
node "D:\opencode\Новая работа\job-radar\scripts\fetch.mjs"

# локальный сбор + публикация в origin/main
node "D:\opencode\Новая работа\job-radar\scripts\fetch.mjs" --publish

# только внешние источники (быстро, без rabota.by)
node "D:\opencode\Новая работа\job-radar\scripts\fetch.mjs" telegram linkedin --publish

# проверить Telegram/LinkedIn без записи в базу
node "D:\opencode\Новая работа\job-radar\scripts\test-sources.mjs"

# пересобрать статистику вручную
node "D:\opencode\Новая работа\job-radar\scripts\export.mjs"

node "D:\opencode\Новая работа\job-radar\scripts\weekly-stats.mjs"
```

Второй скрипт можно запускать с числом дней: `node scripts\weekly-stats.mjs 14`.

## Где смотреть статистику

После каждого сбора автоматически обновляются:

- **`reports/dashboard.html`** — главный файл. Откройте двойным кликом в браузере: итог «что выбрать», сводка, источники, направления, динамика по дням, топ технологий и вакансий.
- **`reports/recommendation.md`** — текстовый вывод: какое направление и специальность выбрать, почему, что учить и план на 4 недели.
- **`reports/recommendation.json`** — тот же вывод в JSON (для других инструментов).
- **`reports/vacancies.csv`** — все вакансии с фильтрами по источнику, опыту, формату и навыкам. Открывается в Excel (разделитель `;`, кодировка UTF-8 с BOM).
- **`reports/stats.csv`** — статистика по дням: новые, entry-level, удалёнка, вилки, разбивка по источникам.
- **`reports/stats.json`** — та же сводка в JSON для других инструментов.

Окно статистики задаётся в `config.json` параметром `exportDays` (по умолчанию 7 дней), окно для вывода «что выбрать» — `recommendDays` (по умолчанию 14 дней).

## Просмотр с телефона

Дашборд адаптирован под мобильный экран. Чтобы открывать его по ссылке:

1. Сделайте репозиторий публичным: **Settings → General → Danger Zone → Change visibility → Make public**. В проекте нет секретов, только вакансии и отчёты.
2. Включите Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Запустите workflow **Job Radar Pages** вручную (Actions → Job Radar Pages → Run workflow) или дождитесь следующего коммита отчётов.

Ссылка будет такой:

```
https://TemaDema.github.io/job-radar/
```

Дальше страница обновляется автоматически после каждого сбора — workflow `pages.yml` срабатывает на изменения в `job-radar/reports/`.

Если делать репозиторий публичным не хочется:

- в мобильном приложении GitHub открывайте `reports/recommendation.md` — Markdown отображается нормально, там есть вывод, рейтинг и план;
- `reports/vacancies.csv` можно скачать и открыть в Excel/Google Sheets;
- альтернатива — Telegram-бот, который присылает краткий итог в личку (нужен свой бот и токен в секретах GitHub).

## Если компьютер выключен

Локальная автоматизация живёт внутри OpenCode и работает, только когда ПК включён и приложение запущено. Поэтому локальный и облачный запуски согласованы через общий журнал `data/runs/YYYY-MM-DD.json`:

- локальный запуск в **08:30** собирает данные, записывает в журнал, какие источники уже обработаны, и с флагом `--publish` коммитит и пушит результат;
- облачный запуск в **08:40** сначала читает этот журнал. Если локальный срез уже сделан — облако пропускает сбор;
- если ПК был выключен, облако в 08:40 собирает само. Когда ПК включится позже, локальный запуск увидит облачную отметку и пропустит сбор, а перед этим подтянет свежие данные из `origin/main`;
- если источник упал (капча на rabota.by, `429` у LinkedIn), он записывается в `sourcesFailed`, и следующий запуск добирает **только недостающие источники**;
- согласование действует в окне 4 часов (`coordinationWindowMinutes`): утренний запуск не блокирует вечерний сбор свежих вакансий.

Дополнительно:

- следующий запуск ищет вакансии за последние `searchPeriodDays` дней (7 по умолчанию) и **восстанавливает пропущенные дневные срезы** по дате публикации — они помечаются как `restored: true`;
- в `data/status.json` видно последний успешный запуск, пропущенные дни (`missedFullDays`), восстановленные срезы (`backfilled`) и статусы источников.

Флаги запуска:

```powershell
# обычный локальный сбор без публикации
node scripts\fetch.mjs

# сбор + коммит и push в origin/main (так работает автоматизация)
node scripts\fetch.mjs --publish

# игнорировать журнал и собрать заново, даже если сегодня уже было
node scripts\fetch.mjs --force --publish
```

Чтобы сбор шёл **без включённого ПК**, используется GitHub Actions:

1. Репозиторий уже создан и запушен: `.github/workflows/job-radar.yml`.
2. В настройках репозитория: **Settings → Actions → General → Workflow permissions → Read and write permissions**.
3. Workflow сам запускается в 08:40 (сбор) и по понедельникам в 09:00 (недельная статистика) по Минску и коммитит свежие данные обратно в репозиторий.

Альтернатива — всегда включённый мини-сервер или Raspberry Pi с тем же `node scripts/fetch.mjs --publish` по cron.

Важно: из облака LinkedIn чаще отдаёт `429`, а rabota.by может показать капчу. Скрипты это переживают: источник помечается как неудачный, остальные собираются, а недостающий доберётся следующим запуском. Полный сбор надёжнее с домашнего IP.

## Как изменить поиск

Всё в `config.json`:

- `queries` — список запросов. У каждого: `id`, `text` (поисковая фраза), `track` (направление для группировки). Для фраз из двух слов используйте кавычки: `"\"техническая поддержка\""`.
- `professionalRole` — поиск по коду профроли hh (например, `96` — программист/разработчик) без текста.
- `searchField: "name"` — искать только в названии вакансии (сильно повышает точность; не меняйте без причины).
- `searchPeriodDays` — глубина поиска (7 дней).
- `maxDescriptionsPerRun` — сколько описаний скачивать за запуск (сейчас 40).
- `requestDelayMs` / `descriptionDelayMs` — паузы между запросами (бережём сайт).
- `sources` — какие источники запускать: `"rabota.by"`, `"telegram"`, `"linkedin"`. Можно переопределить аргументами командной строки: `node scripts\fetch.mjs telegram`.
- `telegram.channels` — список публичных каналов без `@` (например, `"devbyjobs"`). Читается веб-превью `t.me/s/<channel>`, авторизация не нужна.
- `telegram.maxPostsPerChannel`, `maxPerRun`, `delayMs` — сколько последних постов брать с канала, общий лимит за запуск и пауза между каналами.
- `linkedin.location`, `keywords`, `pages`, `periodSeconds`, `maxKeywordsPerRun`, `maxPerRun`, `delayMs` — параметры поиска вакансий LinkedIn. Ключевые слова ротируются по дням (по умолчанию 3 за запуск), чтобы не упираться в лимит. `enabled: false` отключает источник.

Чтобы добавить направление, скопируйте строку запроса и задайте новый `track`. Названия направлений можно менять — они попадут в отчёты.

## Что попадает в базу

Для каждой вакансии: название, компания, город, вилка, валюта, опыт, формат работы, дата публикации, ссылка, направления, найденные технологии, флаг entry-level.

**Entry-level** = опыт «без опыта» **или** в названии/описании есть junior/стажёр/trainee/intern/«без опыта»/«младший».

## Ограничения и этика

- Источники: `rabota.by` (крупнейшая база Беларуси), публичные Telegram-каналы и карточки LinkedIn. Это шире рынка, но всё ещё не всё: нет `dev.by/jobs`, `praca.by`, `belmeta.com` и прямых карьерных страниц.
- `rabota.by` закрыт капчей при слишком частых запросах. Поэтому паузы 1,5–2 сек и лимит описаний; при капче сбор останавливается, а не долбит сайт.
- Telegram читается через публичное веб-превью: видны только последние посты канала, закрытые каналы и посты с фото без текста пропускаются. Список каналов в `config.json` — стартовый, его нужно проверить и дополнить под себя.
- LinkedIn отдаёт только карточки без описания, поэтому навыки определяются по названию вакансии; при частых запросах возможен `429/999` — сбор мягко останавливается.
- Зарплата указана не всегда; в Telegram/LinkedIn она распознаётся эвристикой. Медианы по малым выборкам (1–2 вакансии) — ориентир, а не статистика.
- Автоматизации выполняются, когда OpenCode запущен. Если компьютер выключен, запуск произойдёт позже или пропустится — данные за 7 дней и восстановление срезов частично компенсируют пропуск. Для работы 24/7 используйте GitHub Actions (см. раздел «Если компьютер выключен»).

## Идеи расширения

- Добавить `dev.by/jobs`, `praca.by`, `belmeta.com` и прямые карьерные страницы компаний.
- Собирать описания для всех вакансий (медленнее) — тогда появится сравнение «что требуют на входе» vs «что требуют на мидле».
- Для LinkedIn — дочитывать описание вакансии по ссылке, чтобы точнее определять навыки и опыт.
- Добавить отслеживание курсов и стоимости обучения под выбранное направление.
- Добавить скоринг вакансий под профиль (город, формат, зарплата, стек).
